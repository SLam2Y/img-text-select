# img-text-select — выделение и перевод текста на картинках (Chrome)

Дата: 2026-11-05. Статус: дизайн согласован, ждёт ревью спеки.

## Цель

Текст на картинке выделяется мышью как обычный текст страницы. При выделении рядом всплывает окно: «Копировать», «Перевести» и перевод. Ctrl+C и родное меню правой кнопки работают тоже.

Расширение должно пройти публикацию в Chrome Web Store: без ключей, без своего сервера, весь код внутри пакета.

## Аналоги (почему своё)

- Project Naptha: ровно эта идея, но версия для Chrome заброшена (2014). Живёт только неофициальный порт для Firefox.
- Copyfish, Image to Text, OCR Translator: работают через обводку области и облачный OCR, выделения прямо на картинке нет.

Наше отличие: выделение как у Naptha, локальный OCR с иероглифами, Manifest V3.

## Решения

| Вопрос | Решение |
|---|---|
| Когда распознавать | По кнопке «T» в углу картинки при наведении (картинки ≥ 80×80 px) |
| OCR | PaddleOCR PP-OCRv5 mobile (детекция + распознавание) на onnxruntime-web, локально |
| Языки OCR | По умолчанию модель для английского, китайского и японского. Корейская подключается в настройках |
| Перевод | Google gtx (`translate.googleapis.com/translate_a/single?client=gtx`). При ошибке переключается на Translator API Chrome |
| Язык перевода | По умолчанию русский, меняется в настройках |

## Архитектура (Manifest V3)

```
content script ──URL картинки──▶ service worker ──пиксели──▶ offscreen-страница
   ▲  кнопка T, слой,             fetch картинки,              onnxruntime-web +
   │  окно выделения              перевод, кэш                 PaddleOCR
   └──────────── строки + рамки ◀───────────────────────────────┘
```

1. **content script** (`content.js`). Наведение на `<img>` показывает кнопку «T». После распознавания поверх картинки ложится слой. На каждую строку один прозрачный `<span>` (`color: transparent`, видно только выделение). `transform: scaleX()` подгоняет его ширину под рамку строки, а для вертикальных рамок ставится `writing-mode: vertical-rl`. Слой пересчитывает позицию при resize/scroll (ResizeObserver на картинке). Кэш распознанного по URL хранится в content script на время жизни страницы. Кнопка и окно живут в Shadow DOM. Слой текста лежит в обычном DOM, иначе не работает родное выделение и Ctrl+C.
2. **Окно выделения.** Появляется на `mouseup`, если выделение лежит внутри нашего слоя. Кнопки «Копировать» (`navigator.clipboard.writeText`) и «Перевести». Перевод показывается под кнопками. Окно закрывается кликом мимо и по Esc.
3. **service worker** (`background.js`). `fetch(url)` картинки с правами `<all_urls>`, потому что чужие картинки нельзя прочитать со страницы (canvas taint). Передаёт байты в offscreen и возвращает результат. Перевод через gtx.
4. **offscreen-страница** (`offscreen.html/js`). Создаётся по требованию (`chrome.offscreen`, reason `WORKERS`). Загружает модели из пакета и выполняет детекцию, затем распознавание по каждой рамке. Возвращает `[{text, box: [[x,y]×4]}]` в координатах исходной картинки.
5. **Translator API (запасной).** Вызывается из content script (API доступен в окне). Если API нет или модель не скачана, окно показывает «Нет перевода» и ссылку на translate.google.com с текстом.
6. **Настройки** (`options.html`, `chrome.storage.sync`): язык перевода, корейская модель вкл/выкл.

Внешний код из сети не грузится. JS, WASM и модели лежат в пакете. Размер пакета ≈ 50 МБ (модели 35 МБ, WASM ORT 14 МБ). Словари PP-OCRv5 дополняются классом пробела в конце, иначе модель не стартует.

## Ошибки

- Картинку не удалось скачать: на кнопке «T» подсказка «Не удалось загрузить картинку».
- `blob:` картинки страницы не читаются из расширения: «Не удалось загрузить картинку».
- Текст не найден: подсказка «Текст не найден».
- Модель упала или кончилась память: подсказка «Ошибка распознавания», подробности в консоли offscreen.
- Перевод: gtx не ответил (сеть, 429), тогда Translator API. Не ответил и он, тогда «Нет перевода» + ссылка.

## Вне рамок (YAGNI)

Фоны CSS, `<canvas>`, видео, обводка произвольной области, PDF, свой сервер, платный Cloud Translation, автоопределение языка OCR.

## Риски

- Готовые ONNX-модели PP-OCRv5 и их пред/постобработку (DB-детекция, CTC-декодирование, словарь) проверить первым шагом плана. Запасной путь — модели PP-OCRv4 из RapidOCR.
- onnxruntime-web в offscreen под CSP MV3: нужен `wasm-unsafe-eval` в `content_security_policy.extension_pages`.
- Translator API может не работать в content script. Тогда вызывать его из offscreen-страницы. Проверить на шаге перевода.
- Вертикальный японский: на тестовой картинке распознаётся точно. На реальной манге с шумом может быть хуже.
- gtx неофициальный, Google может ограничить. Для этого есть запасной путь.
- Публикация: нужна политика приватности. Картинки не уходят никуда, выделенный текст уходит в Google при нажатии «Перевести».

## Проверка

- `test/page.html` с картинками: английский, китайский, японский горизонтальный, вертикальная манга, мелкий текст.
- Playwright + headless Chromium с загруженным распакованным расширением. Скрипт навода на картинку, жмёт «T», ждёт слой, сверяет распознанный текст с ожидаемым по подстроке, выделяет строку и проверяет, что окно появилось и перевод не пустой.
- Самопроверка постобработки (CTC-декодер, сортировка рамок) маленьким `node --test` без браузера.
